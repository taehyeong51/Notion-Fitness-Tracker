# 로컬 웹 검증 결과

검증일: 2026-10-05 · Asia/Seoul

FastAPI 읽기 서버와 React 웹을 구현했다. 실제 Notion 조회, 계산 대조, Chromium·WebKit 렌더링과 내보내기를 확인했다. 사용법은 [실행 안내](local-dashboard-runbook.md), 화면 기준은 [채택한 목업](assets/local-dashboard-mockup.png)이다.

## 자동 검사

| 검사 | 결과 |
|---|---|
| Python 전체 | 141개 통과. 새 웹 85개와 기존 Notion 56개 |
| 웹 설정 | Vitest 10개 통과 |
| 브라우저 | Chromium·WebKit 각각 26개. 기존 50개 전체 실행과 추가 스냅샷 충돌 복구 2개 통과 |
| 프로덕션 빌드 | TypeScript 검사·Vite 빌드 통과 |
| 설치 재실행 | Python 해시 잠금·`npm ci`·빌드·공유 라이브러리 검증 통과 |
| 로컬 서버 | 재시작 캐시, 실제 분석 요청, LAN 바인딩·동일 Origin 요청 확인 |

브라우저는 1440×900·1920×1080, 768px 태블릿, 390×844·430×932·320px 모바일 폭을 검사했다. 첫 화면의 요약·핵심 종목과 PC의 주간·근육 차트가 기준 영역에 들어오며 페이지 전체의 가로 넘침이 없다. 테마, 종목 재정렬, 터치 툴팁, 키보드, 실패·재시도, 자정 후 안내, CSV·PNG도 검사했다.

변경·삭제·복구·조회 중 수정·관계 페이지네이션·시간 초과는 가짜 전송기로 검사했다. 실제 운동 기록을 바꿔 테스트하지 않았다. 웹 읽기 어댑터는 조회용 GET과 데이터 소스 query POST만 허용한다.

첫 GitHub CI에서 `tests/dashboard`가 앱 패키지 이름과 충돌하는 문제를 확인해 `tests/test_dashboard`로 바꿨다. 로컬 editable 설치를 제거한 상태에서도 같은 전체 검사 명령으로 141개가 통과했다.

## 실제 원본 대조

2026-10-05 07:48의 성공 조회 기준이다. 과거 Notion 문서의 567세트와 구분한다.

| 항목 | 대조 결과 |
|---|---:|
| 원본 세션 / 세트 / 종목 | 28 / 589 / 67 |
| 날짜를 정할 수 없는 세트 | 23. 모두 세션 관계 없음 |
| 전체 완료 집계 | 28회 / 566세트 |
| 최근 12주: 2026-07-14–10-05 | 27회 / 555세트 |
| 이번 주: 2026-10-05–10-11 | 현재 0회 / 0세트 |
| 최근 12주 고유 Session×Exercise | 172 |
| 기본 최근 수행 / 더 보기 | 3회 / 13회 확인 |
| 최근 12주 세트 CSV | 555행, UTF-8 BOM |

주간 유형 합, 근육·종목·분할의 세트 합이 555로 일치한다. 주간·분할 세션 합은 27, 종목 빈도 합은 172다. 날짜별 데드리프트 e1RM은 원본 중량·반복에서 독립 계산한 최고값과 일치한다. 140kg×4회의 표시값은 158.7kg이다.

10월 5일은 월요일이다. 이번 주 0은 조회 실패가 아니라 새 주에 완료 기록이 없는 결과다. 최근 12주의 시작일도 하루 이동해 7월 13일의 1회·11세트가 기간 밖으로 빠졌다. 첫 두 요약은 이번 주, 네 번째 요약과 차트는 선택 기간을 따른다.

실제 풀업의 0kg 입력은 방식 미확인 관측 반복으로 유지한다. 같은 입력 중량의 반복 차트에서도 방식별 시리즈를 분리한다. e1RM·확인 PR·발전 지수는 만들지 않는다. 확인 조건과 외부중량 의미가 없는 현재 원본에서는 C10·외부중량 볼륨에 필요한 정보와 사유를 표시한다.

## 화면과 성능

실제 데이터로 밝은 PC와 어두운 모바일 화면을 렌더링했다. 요약 4개 → 핵심 종목 → 주간·근육 분석 → 분할·빈도 → 상세·최근 수행 → 건강 순서를 유지한다. 목업의 예시 수치·예시 그래프를 현재 데이터로 대체했으며 조건 미확인 선은 점선이다. 근육별 막대는 모든 라벨과 개수를 표시한다.

실제 화면·CSV·PNG·측정 JSON은 개인 기록을 포함하므로 `.local/web-verification/`에 보관하고 Git에서 제외했다. 반복 가능한 합성 화면 캡처는 브라우저 검사의 `web/test-results/`에 생성된다.

| 측정 | 결과와 범위 |
|---|---|
| 캐시에서 핵심 화면 표시 | 단일 PC 브라우저 3회: 388·422·681ms |
| 기간 클릭→새 요약 DOM | 4주 348ms, 12주 271ms, 전체 237ms. 같은 스냅샷 재계산 |
| 분석 API | 별도 9회: 중앙값 38.76ms, 최대 47.90ms |
| 필수·선택 원본 전체 조회 | 약 25.5–27.6초. 초당 2회 제한과 원본 지문 재검증 포함 |

캐시 표시 1초 목표는 위 단일 브라우저 측정에서 충족했다. 필터 300ms 목표는 첫 4주 변경에서 48ms 초과했다. 병렬 브라우저 검사 중 초기 표시가 2초를 넘은 실행도 있어 모든 기기의 고정 응답 시간을 보장하지 않는다. 조회 진행은 즉시 표시하며 필터 변경으로 전체 Notion 조회를 다시 하지 않는다.

## 남은 기기 확인

실제 개인 Windows/macOS PC 설치와 물리 iPhone의 같은 LAN 접속은 이 클라우드에서 실행하지 못했다. WebKit·모바일 에뮬레이션과 서버 LAN 검사까지 확인했다. 개인 PC에서는 [실행 안내](local-dashboard-runbook.md)의 설치·원본 연결 후 `--lan`으로 확인한다. PC 종료·절전 또는 서버 종료 시 휴대폰에서 새 데이터를 받을 수 없다.

클라우드 준비 파일의 저장과 환경 Publish는 별도다. 새 작업에서의 스냅샷 복원은 이번 구현 검사의 결과로 간주하지 않는다.
