# Fitness Tracker · Notion 네이티브 분석

[계획 문서](fitness-tracker-audit-and-plan-2026-10-03.md)를 교육 Plus에서 구현합니다. 일반 페이지, 네이티브 차트와 연결 테이블을 사용하며 HTML과 Business 전용 Dashboard view는 사용하지 않습니다.

[실제 분석 페이지](https://www.notion.so/3eeac97b856381f09764c396b57d81e5)에 10개 후보를 표현하는 차트·종목별 탭과 연결 보기를 생성했습니다. 관측된 수행 추세는 표시하되, 과거 측정조건이 확인되지 않은 수행을 동일 조건의 발전 지수로 사용하지 않습니다. 최종 검증 결과와 기기 확인 범위는 계획 문서의 21–22절에 기록합니다.

## 실행 환경

Python 3.12 이상과 표준 라이브러리만 사용합니다. 토큰은 Codex 환경 설정의 `NOTION_TOKEN` secret으로 공급하고 HTTPS 대상은 `api.notion.com`입니다. Notion 연결에 Fitness Tracker 및 원본 3개 DB의 읽기·추가·수정 권한이 필요합니다. 토큰을 채팅·파일·GitHub·로그에 입력하지 않습니다.

```bash
cd /workspace/Notion-Fitness-Tracker
python3 -m unittest discover -s tests -v
python3 -m notion inspect
```

`inspect`는 실제 부모/data source ID와 스키마를 `.local/notion-discovery.json`에 저장하는 읽기 전용 명령입니다. `.local/`은 Git에서 제외되고 파일 권한은 600입니다. 원본 운동 데이터와 로컬 설정은 GitHub에 올리지 않습니다.

`notion/config.example.json`을 `.local/notion-config.json`으로 복사하고 발견한 실제 ID·속성명으로 채웁니다. 기존 환경에는 검증한 설정과 배포 상태가 보존됩니다. 다른 워크스페이스에서 제목·ID를 추측하거나 이 환경의 상태 파일을 재사용하지 않습니다.

```bash
python3 -m notion prepare
python3 -m notion plan
python3 -m notion apply
python3 -m notion verify
```

- `prepare`: 검증한 Workout Sessions / Exercise Sets 스키마에 `NFT …` 표시용 속성·롤업·수식을 추가합니다. 원본의 중량·반복·날짜·분류·메모는 보존합니다. 현재 명명법을 전제로 하므로 다른 스키마에는 바로 적용하지 않습니다.
- `plan`: 전체 원본과 관계를 페이지네이션하고 계산·진단을 수행합니다. Notion 쓰기는 하지 않습니다.
- `apply`: 원본 아래 분석 페이지, 네이티브 차트와 테이블을 생성/대조합니다. 관리 Key가 있는 주간 집계 행만 동기화합니다. 변경 없는 재실행은 집계 행을 다시 만들지 않습니다.
- `verify`: 실계정 수식을 독립 계산과 대조하고 차트마다 실제 필터 조회 결과를 대조합니다. `--original .local/notion-original.json`을 지정하면 배포 전 원본 ID·입력 속성과도 비교합니다. 읽기 전용입니다.

API 버전은 `2026-03-11`입니다. 공식 Views API의 `create_database`로 원본 data source를 참조하는 연결 보기를 만들고, 생성한 설정을 다시 읽어 검증합니다. 요청 결과가 불명확한 생성 작업은 자동으로 다시 만들지 않습니다.

## 데이터와 갱신

기본 `chart_source_mode`는 `native`입니다. 차트 22개와 연결 테이블 6개 중, 차트 전체와 테이블 5개가 원본 DB를 직접 읽습니다. 기본 14개 차트, 중량 종목/풀업 조건 탭 4개, 분석 홈의 숫자 차트 2개와 주간 차트 2개로 구성됩니다. 클라우드 프로세스가 종료되어도 원본을 직접 읽는 보기는 Notion에서 재계산됩니다.

C07은 세트 수를 빈도로 사용하지 않고 `Session Key`를 `unique`로 집계합니다. C05는 주 근육 하나만 배정하며 미상과 미연결을 보존합니다. C03은 월별·반복 구간별 최고 중량이며 합계나 누적이 아닙니다. 주간 세션과 세트, 분할별 각각의 분모, 중량과 풀업 반복 지수를 분리합니다.

현재 미분류 495세트를 작업 세트로 바꾸지 않았고, 미연결 9세트의 종목을 추측하지 않았습니다. 풀업은 그립이 명시된 3세트와 미확인 17세트를 별도 탭에 표시합니다. 중량이 0/빈 값인 풀업을 e1RM 0으로 표시하지 않습니다.

기구·그립·총중량/한쪽 중량/추가 중량 같은 측정조건은 `NFT Measurement Condition`에 기록하고 `NFT Condition Confirmed`로 확인합니다. 운동 사전의 현재 속성을 과거 세트의 사실로 소급하지 않습니다. 조건 미확인 추세는 관측치로 명시하며 C10 발전 지수에서는 제외합니다.

비교 준비 테이블에서 확정 조건, 기준 세트 관계 `NFT Baseline`, 반올림 전 기준값 `NFT Baseline Value`, 버전 `NFT Baseline Version`을 입력합니다. 기준은 선정 기간 내 해당 조건의 유효한 일별 최고 수행으로 선택합니다. 중량 종목은 Epley e1RM, 풀업은 반복 수를 사용합니다. 기준 관계·조건·종목·값이 불일치하거나 기준 원본이 변경되면 이전 버전의 지수가 비워집니다. 새로운 조건에 자동으로 기준을 추정하거나 기존 버전을 조용히 재설정하지 않습니다.

최근 12주는 고정 날짜가 아닌 네이티브 `today()` 수식으로 이동합니다. 주 시작은 날짜 속성에서 월요일로 계산합니다. 날짜만 저장된 세션을 사용하며, 계정의 날짜/시간대 설정은 실제 기기 확인 때 함께 확인합니다.

C06 상위 10개의 **종목 선정**과 주간 요약 테이블은 마지막 실행 시각 기준입니다. 상위 종목의 세트 수 자체는 원본에서 갱신됩니다. 새 기록 때문에 순위가 바뀌면 `apply`를 실행해 선정과 주간 표를 새로 계산합니다. 이 두 항목을 영구 자동 집계라고 주장하지 않습니다.

```bash
python3 -m notion watch --interval 90
```

`watch`는 선택적인 반복 대조 명령입니다. 해당 프로세스가 켜져 있을 때만 동작하고 새 클라우드 작업에서는 다시 시작해야 합니다. **관리 차트의 기본 설정·필터도 다시 적용하므로**, 차트에서 개인 필터를 바꾸며 사용하는 동안 상시 실행하지 않습니다. API 제한과 원본 규모에 따라 한 주기가 90초를 넘을 수 있으며, 영구 서비스나 2분 갱신 보장을 제공하지 않습니다.

명시적 `projection` 모드는 이전 대안으로 남아 있지만 기본 배포에는 사용하지 않습니다. 이 모드에서는 5개 파생 DB와 상태 갱신 프로세스가 필요합니다.

## 실제 검증

```bash
python3 -m notion live-check
```

이 명령은 별도 임시 DB에 검증용 세션/세트를 만들고, 중량 수정·최고값 보관/복구·날짜 이동·기준 변경·조건 불일치의 네이티브 재계산을 검사합니다. 실제 운동 DB에는 쓰지 않으며 임시 페이지는 종료 시 보관합니다. 쓰기가 필요한 검증이므로 실제 구현/검증이 요청된 범위에서만 실행합니다.

실계정 API 검증과 iPhone Notion/Safari·PC 화면 검증은 구분합니다. 현재 페이지는 API로 확인한 한 열 배치입니다. 실제 기기의 가독성, 탭과 원본 열기, PC 두 열 배치는 별도 화면 확인이 필요합니다.
